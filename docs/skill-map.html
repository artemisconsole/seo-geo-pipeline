How a skill runs in Claude Code

Every skill follows the same spine — this is the "how they connect" picture.
1 · Trigger
Someone types /command (PIC/JR), or a scheduled task fires it.
2 · Read context
Skill loads layered context from the repo:
  • CLAUDE.md (rules + gates)
  • core/ (format · industry · market)
  • project/brand + config (tier · access)
3 · Do the work
Pulls & writes via Connectors, offloads heavy reads to subagents, and hooks lint on save.
4 · Write output
To the Sheet/Doc (connector) + content/ & decisions.md (GitHub) — never straight to the client.
5 · Gate
PIC → SEN → AM/PM → client. Skill updates Status and names who approves next.

Conflict order when layers disagree: brand > project/overrides > format > content-type > industry > market > core. tier decides what to do & how deep; access (cms none/limited/full) decides how far Claude acts — both chosen at /new-project.
